# v1.2.3 保存逻辑与验证

本次处理 v1.2.2 审阅问题 2、3、13。版本从 1.2.2 升为 1.2.3，录制文件 schema 保持兼容。

## 保存流程

1. 启动时独占创建新会话目录，准备 bag 和各视频队列，全部成功后发布当前会话。目录创建、后端打开或话题登记失败都返回具体错误。相同秒内的新会话使用 `_N` 后缀。
2. 普通 ROS 回调捕获所属会话并投递到该会话的队列。TRANSIENT_LOCAL 样本在缓存锁内更新缓存并选择当前会话：新会话尚未启动时由开录重放，已经启动时由回调补写，避免连续录制遗漏静态 TF 等持久状态。工作任务不重新查找当前 writer；QoS 仅在首次登记话题时查询和序列化，录制中补订话题的登记由 rosbag worker 完成。
3. 标签、标注的模型变动同步至引擎内存快照。录制过程中不写元数据；区间沿用原有规则，只导出已经闭合的标注。
4. 停止按钮、关闭窗口、ROS shutdown、Controller 析构统一停录。先同步最新快照、切断新消息准入并冻结时长；所有队列先停止接收，再在会话锁外等待排空。
5. 分别关闭视频、保存 CSV、关闭 bag。任一后端失败仍继续收尾其他后端，最后保存 `session.yaml`；汇总写入与收尾错误供 GUI 和日志报告。
6. 成功时刷新历史列表并清空在线标签选择；失败时保留模型中的标签、标注并显示错误。历史列表扫描具有 GUI 异常边界，损坏文件不导致保存回调或程序退出。

收尾采用同步等待，时长不包含队列排空或文件写入耗时。重复停止返回首次结果，不再次写入。

`session.yaml`、bag 的 `metadata.yaml` 和视频 CSV 都普通直接写入目标文件，检查打开、写入、flush 和 close。YAML 在打开目标前先完成序列化。没有临时文件、rename、录制中 checkpoint、恢复元数据或恢复入口；写入中断可能留下不完整文件。

## 复审与已知限制

GUI 测试完成后进行了独立复审。复审指出普通写入失败留下的截断 YAML 可能在后续历史扫描时触发异常，已为 GUI 扫描入口补齐异常边界，并保留读取错误诊断；文件不进行恢复或自动修复。

补丁经过回归测试和 GUI 复测后，再次核对 Controller 退出、引擎会话隔离、队列唤醒及后端直接写入边界，两路独立复审均未发现本次保存修改中剩余的实际 P1/P2 问题。复审未重新覆盖原汇总中其他回放、时间轴、QoS 和曲线/相机 UI 问题。

后续暂存审阅发现并修复了两处问题：跨会话延迟的 TRANSIENT_LOCAL 回调更新缓存后被丢弃，以及每条消息重复查询、序列化 QoS。新增测试验证持久样本在当前及下一会话各出现一次、时间戳不早于会话起点，普通延迟消息不进入新会话，以及开录后新出现的话题完整保留消息与 QoS。将新测试链接到修复前引擎时，持久样本测试因实际 0 条、预期 1 条失败；修复后通过。默认 release 构建 40 个包成功，7 组相关测试全部通过。相同的 20,000 条 String 回调基准中，每条耗时从约 54 微秒降至 0.69 微秒，三轮均正常保存；该数字不代表 DDS 端到端吞吐。

`test_usage_help` 仍要求旧的硬编码绝对路径，而当前帮助文本使用 `<config_file_path>`，该基线失败与本次保存修改无关。

SIGINT 场景发现既有 MP4 尾帧显示时长问题：左路有 278 个编码包，CSV 有 278 行，默认 FFmpeg 解码显示 277 帧；最后包 PTS 恰好落在 edit list 右端而被丢弃显示。`ffprobe -ignore_editlist 1` 可解码全部 278 帧。原编码路径同样没有设置正 packet duration；本次未调整视频时间轴或包时长，这一问题仍需独立修复。
